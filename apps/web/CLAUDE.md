# shadcn/ui here uses Base UI, NOT Radix

The `components.json`/`ui/*.tsx` generated by the CLI use `@base-ui/react`
(shadcn migrated off Radix). Compose triggers/closes with the
**`render={<Element />}`** prop, NOT `asChild` + children -- `asChild` is
SILENTLY ignored (no error), the Trigger still renders its OWN default
`<button>` around whatever child `<Button>` you pass as children, and the
result is a nested `<button>` (React hydration error, FOUND LIVE while
testing Group A `ChangelogDialog`/`UserMenu`). Correct example: see
`DialogPrimitive.Close` in `ui/dialog.tsx`.

`DropdownMenuLabel` (`MenuPrimitive.GroupLabel`) MUST also be wrapped in
`<DropdownMenuGroup>` -- unlike Radix, where it can stand alone, Base UI
throws a runtime error ("MenuGroupContext is missing") if it is not. Also
FOUND LIVE (`UserMenu`).

`SelectItem` children MUST be a single string, NOT several JSX
expressions/text pieces (`{a}{b}` or `{a} literal`) -- Base UI Select
extracts the item's label/value for typeahead (`useTypeahead`) and
keyboard-select matching (`SelectRoot.js` calls `.toLowerCase()` on the
extracted value); if the children are an array of nodes (not a single
string) the extracted value is not a string → `Uncaught TypeError:
c.toLowerCase is not a function`, which crashes the ENTIRE Select (not just
that item). FOUND LIVE in Group C (`AddUserForm`'s Role select, two children
`{r.name}{cond ? ... : ""}`) -- fix: merge them into one
`{cond ? `${a} — ${b}` : a}`.

A `<Select>` whose default/initial value is NOT the first rendered item
(e.g. an "all" sentinel selected before the popup has ever been opened)
shows the RAW VALUE in the trigger (`__all__`), not the item's label --
`<Select.Value>` can only resolve labels from items that HAVE rendered
(`SelectContent` is portalled and not mounted until the popup is opened for
the first time). Fix: pass the `items` prop to `<Select>` (`Select.Root`) --
a `Record<string, ReactNode>` of value->label -- which is the API Base UI
designed exactly for resolving labels without waiting for the popup to
mount. FOUND LIVE in Group D (`FilterBar`'s country/industry/actor selects,
default value `"__all__"` before the user ever opens the dropdown).

Base UI `Checkbox` is NOT a native `<input type="checkbox">` (it is a
role-based `<span>`), but it renders a hidden native `<input>` next to it for
form participation IF given a `name` prop -- its value defaults to the
`name` itself (NOT `"on"` like a plain native checkbox), and when UNCHECKED
there is no input in the form at all (unless `uncheckedValue` is set). So
extraction via `FormData` must check whether the key EXISTS
(`fd.get('x') != null`), NOT `=== 'on'`. FOUND in Group E
(`CveTicketTab`'s `escalation_required` checkbox, uncontrolled ticket form).
