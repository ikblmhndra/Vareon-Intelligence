# UI data audit: does what the pages show match the data?

Status: findings (2026-10-24). Dev instance 172.25.1.77 running 0.8.2 (`origin/Dev`, which
includes the dashboard and newsroom redesign). Method: read each page, then compare its
numbers with the API it calls and with an independent recount from the raw list endpoints.
Read-only; nothing was written. Companion to `docs/LLM_ASSIST_REDESIGN.md` and
`docs/TARGET_ARCHITECTURE.md`.

## Quick fixes (independent of the redesign)

Each is small and can ship in the current UI. Items 1-9 are implemented in release 0.8.3; item 10
is left to an administrator:

1. Rename the toggle to "Threat news only" and show incidents only from `confirmed_incident`;
   make the brief use the same filter (U1, U2, U7).
2. Bucket empty country as "Unknown" (U3); hide or grey out trend arrows when
   `prev_period_reliable` is false (U4).
3. "Open critical" = critical and not acknowledged and not FP; KEV count from the same set (U6).
4. Recap: refuse to store a parsed but empty reply (HTTP 502, old row kept); show an empty or
   unreadable recap as failed instead of "nothing was dropped" (U13).
5. Actor matcher: drop names that ATT&CK lists as software (and not as a group) from the actor
   dictionary, mask them in the text, and match the longest name first (U8). U9 stays open until
   its cause is confirmed.
6. Scraper dates: for the 61 scrapers without `date_path`, read `article:published_time`,
   JSON-LD `datePublished` or the RSS `pubDate` before falling back to scrape time, and store
   which one was used (U10).
7. X Intel and other feed-backed pages: show the Data health status for their feed (U16).
8. CVE rating: rate on the whole set (unacknowledged counts against MTTA), and one shared
   "open critical" definition used by all three pages (U19, U20).
9. Decode HTML entities in titles at ingest and drop or rename file-name titles (U27).
10. Give users their real role; keep superadmin to one or two accounts (U28). This is an account
    change for an administrator, not a code change.

## What the redesign changes in the UI

See `docs/TARGET_ARCHITECTURE.md` section 5 for the information architecture. The audit adds:

- Every number has one definition and one name across pages (articles vs stories vs
  confirmed incidents), served by one read model, so Dashboard and Exec cannot disagree.
- Every derived fact shows how it was obtained (explicit, dictionary, inferred, LLM, analyst)
  and can be confirmed or rejected in place; rejections feed the extractors (U8, U9, U11).
- Trend widgets refuse to compare against an unreliable baseline.
- Feed-backed pages carry their source health.
- Grades shown are Admiralty from graded sources and story corroboration, not LLM confidence.
