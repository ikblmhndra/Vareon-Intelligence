## 0.8.18 — CVE Tracker: paginated Ticketing table, selectable CVE list sort

Release: not yet tagged (branch `claude/cve-ticketing-pagination`; merge to `origin/Dev` for the dev test, then PR to
`main`). Patch on top of 0.8.16 (prod since 2026-11-16). 0.8.17 (IOC enrichment fix, branch
`fix/ioc-enrich-invalid-url`) is a separate release; whichever merges second rebases its CHANGELOG entry on top.

### What changes in prod

- Web only. CVE Tracker → Ticketing: the tickets table shows 25 rows per page (25/50/100 via "Rows per page", remembered
  per browser in `localStorage` key `vareon.pageSize.cveTickets`) with the same numbered pager as the CVE list and
  Scrapers. Prod had 1 300 Open tickets rendered in one table.
- The status counts (Open / In Progress / Resolved / Risk Accepted / Closed), search and "Include false positives" still
  work on the full ticket list, as before. Changing status, search, the switch or the page size returns to page 1.
- The ticket panel on the right shows the picked ticket, or the first ticket of the current page.
- `GET /api/cve/tickets` is unchanged (it still returns every ticket; the page header count, the CVE list and the CVE
  detail card read the same response).

- CVE Tracker → CVEs: a "Sort by" select in the list card (detected, published, risk; always newest or highest
  first). The default is now **detected** (newest found first); before 0.8.18 the list was always sorted by risk. The
  subtitle names the active sort ("445 CVEs - sorted by detected date"), and changing it returns to page 1. Filters,
  tabs and paging work with every sort. The choice is not remembered across page loads.
- API: `GET /api/cve` accepts `sort_by=detected` (orders by `cve_tracker.detected_on`, nulls last, `id` as tie-breaker).
  The API default stays `published`; other values are unchanged. `docs/openapi.json` changes only in that pattern.

### Rollback

`make deploy` restores the `:prev` images on a failed health check. Rolling back to 0.8.16 only brings back the
unpaginated table.

### Known risks

  Rendering is what got cheaper; the payload did not change.
