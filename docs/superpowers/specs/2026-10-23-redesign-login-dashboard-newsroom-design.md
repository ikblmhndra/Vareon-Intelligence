# Redesign: Login, Dashboard, Newsroom

- Date: 2026-10-23
- Status: Draft, awaiting user review
- Mockups (approved direction): https://claude.ai/artifact/879LVfcCxbJ47nZ6tmMoR1
  (Login, "Dashboard (A + C)", Newsroom tab "Usulan · N1 + N3")

## 1. Goal

Rebuild three pages of `apps/web` so they serve two audiences at once:

- **Managers / client demos** read the top of the dashboard in about 30 seconds: where the activity
  is (world map), what happened (brief), what needs action (three counts).
- **SOC/CTI analysts** scroll down for the operational detail and use the Newsroom to read news.

The dashboard also gains data that already exists in the database but is not shown today:
ransomware, CVE exposure against the client's tech stack, trending entities, and client context
(watchlist, PIR).

### Success criteria

1. The three pages match the approved mockups in layout and hierarchy, in light and dark themes, at
   1440 px and 375 px wide.
2. The login page makes no API call before the user signs in and shows no platform numbers.
3. Each new dashboard section gets its numbers from a documented endpoint scoped to the active
   client (`X-Client-ID`) where the data is per client. No section shows hard-coded or made-up figures.
4. Every dashboard section loads on its own: one failing endpoint shows an error in its own card and
   leaves the rest of the page working (the current pattern of independent `useQuery`s).
5. The Newsroom keeps every capability of the current six panels (APAC, Global, Local, Ransomware,
   Watchlist, Tech Stack), the article modal, and the admin "Filtered Articles" tab.
6. CI passes: ruff, mypy (core/scraper), pytest unit + integration, web lint + typecheck + build, and
   the API contract drift check (`docs/openapi.json`, `schema.d.ts` regenerated).

### Out of scope

- Other pages (CVE, Intelligence, Exec, Scrapers, ...) keep their current look. The theme tokens do
  not change, so they stay consistent.
- Malware and CVE as Newsroom topics. Articles have no stored link to malware families or CVE IDs;
  adding that is enrichment pipeline work for a later phase.
- An LLM-written daily brief. Daily recaps are only generated by hand today
  (`POST /api/recap/generate?kind=daily`), so the dashboard cannot depend on one existing.
- IOC widgets (not chosen by the user).

## 2. Constraints carried over

- Theme tokens in `apps/web/src/app/globals.css` (Privy red `--primary`, Heartful Burgundy `--hero`,
  `--hero-*` foregrounds) stay as they are. New colors go in as tokens with light and dark values.
- No `backdrop-blur` (performance, commit `8f0655e`). Prose uses theme tokens, not `prose-invert`.
- Test dialogs and panels in both light and dark themes.
- shadcn/ui here is built on Base UI (`render={<X/>}`, not `asChild`); see `apps/web/CLAUDE.md`.
- Next.js 16: read `node_modules/next/dist/docs/` before writing route code; `proxy.ts` is the guard.
- Fonts stay: Google Sans Flex for UI, IBM Plex Mono (`font-code`) for data values (CVE IDs, TTP IDs,
  counts in tables).

## 3. Login

### Layout

Two columns at `md` and up, one column below (the burgundy panel shrinks to a short header above the
form on mobile).

- **Left panel** (`bg-hero`, `text-hero-foreground`): brand mark + name, eyebrow
  "Cyber threat intelligence", headline "Tahu lebih dulu. Bertindak lebih cepat.", three static
  lines on what the platform does (news scored and summarised; CVEs matched to the tech stack;
  actors, TTPs and IOCs mapped to MITRE ATT&CK), and a footer "Akses terbatas untuk pengguna
  terdaftar". Behind it a decorative dot map of the continents drawn from a static shape (no data).
- **Right panel**: "Masuk" heading, username, password, submit, and the line
  "Lupa password? Hubungi admin platform." Keeps the current `LoginForm` logic unchanged:
  `safeRedirect`, error `role="alert"`, the pending state, and the `<Suspense>` wrapper.

### Rules

- No numbers, counts, source lists, or anything fetched from the API on this page.
- The dot map is a pure client-side drawing from a hard-coded land mask, shared with the dashboard map
  component as its background layer (see 4.2), and it respects `prefers-reduced-motion` (static).
- The copy is fixed in the component. Language: Indonesian headline and helper text, English field
  labels ("Username", "Password", "Sign in"), as in the mockup.

### Files

- `apps/web/src/app/login/page.tsx` (rewritten layout, same form logic).
- New `apps/web/src/components/world-dots.tsx`: canvas dot map with an optional `points` prop. With no
  points it is the login background; with points it is the dashboard map base.

## 4. Dashboard

### 4.1 Page structure (top to bottom)

1. **Header**: date ("Kamis, 23 Oktober"), active client name, "updated" time, and the period control
   (24h / 7d / 30d / All). The period control drives every section that takes a period. The current
   "incidents only" toggle stays in the filter bar.
2. **Signal hero** (one `bg-hero` band, two parts):
   - **Signal map** (left): world dot map. One glowing point per country, size = incident articles
     + ransomware victims for that country in the period. The client's countries
     (`client_countries`) get a white ring. Hover or focus on a point shows a tooltip: country name,
     incident count, ransomware victim count, top actor and top sector. Clicking a point opens the
     Newsroom filtered to that country. Points are keyboard focusable and the map has a text
     alternative (a visually hidden list of the top 10 countries with their counts).
   - **Brief + actions** (right): eyebrow "Brief", one generated headline sentence and one supporting
     sentence (see 4.3), then three action rows, each a link:
     - KEV CVEs matching the tech stack, with "N tanpa tiket" → `/cve` filtered to KEV.
     - Ransomware victims in the client's countries → Newsroom ransomware rubric filtered.
     - Watchlist / PIR hits since the start of the period → Newsroom watchlist rubric.
3. **KPI strip** (five cells): Articles (with delta), Confirmed incidents (with delta), Ransomware
   victims (with APAC count), Open critical CVEs (with KEV count), Threat actors in the news (with
   "new this period").
4. **Card grid** (12 columns at `lg`):
   - "Perlu dibaca" (7 cols): top 4 articles by priority (see 5.3), each with its badges and why it
     matters (watchlist / tech stack / PIR match).
   - "Naik tajam" (5 cols): top 4 trending entities (actors and TTPs) with count and change.
   - "Ransomware" (4 cols): weekly victims, last 8 weeks (area line), and the top 3 groups.
   - "CVE exposure" (4 cols): top 3 CVEs matching the tech stack, ordered KEV first then CVSS, with
     ticket state; last row = tickets closed in the period and their mean time to close.
   - "Konteks klien" (4 cols): watchlist hits, active PIRs with new articles, newest campaign cluster.
   - "Artikel dari waktu ke waktu" (8 cols): all articles vs confirmed incidents (two lines).
   - "Industri disasar" (4 cols): top industries, "General" excluded (current behaviour kept).
5. **Threat Actor Room** section and "Top MITRE ATT&CK TTPs" chart from today's dashboard move below
   the grid, unchanged in data, restyled to the new cards.

The existing "Need Attention" band (`attention-band.tsx`) is replaced by the signal hero; its sector
logic is not carried over.

### 4.2 Map rendering

- Canvas, drawn by `world-dots.tsx`. The land mask is a small static equirectangular bitmap (about
  180 × 90 cells) committed as a TypeScript array, giving recognisable continents. Country points are
  placed by centroid from a static ISO-2 → (lon, lat) table.
- The map does not use a new map library. The current `components/dashboard/country-map.tsx` is only
  imported by the dashboard page, so it is deleted together with `attention-band.tsx`.
- Colors come from tokens read with `getComputedStyle` (`--hero-accent` for incidents,
  `--hero-eyebrow` for ransomware, `--hero-foreground` for the client ring), redrawn on theme change.

### 4.3 Brief text

Deterministic, no LLM. The API builds it from the same numbers the page shows:

- Headline: the top trending entity and the top attention item, for example
  "Qilin naik 340% dan 3 CVE KEV cocok dengan tech stack klien."
- Supporting sentence: incident change vs the previous period and the two largest drivers (news
  types or industries).

When there is nothing notable (no trend above threshold, no KEV, no hits) the brief says so
plainly ("Tidak ada lonjakan atau CVE KEV baru pada periode ini."). The brief links to the latest
weekly recap (`/recap`).

### 4.4 New API endpoints

All under the existing `articles` router prefix `/api` with `require_auth`, client scoped through
`effective_client_id` where marked. Each takes `days` (same values as `/api/dashboard`; empty =
all time) and returns `generated_at`. Logic lives in a new service module
`apps/api/src/cti_api/services/dashboard_overview.py`; repositories get new query methods in
`cti_core.db.repositories`.

| Endpoint | Client scoped | Returns |
| --- | --- | --- |
| `GET /api/dashboard/map` | yes (client countries only) | `points[]`: `country_code`, `incidents`, `ransomware_victims`, `top_actor`, `top_industry`; `client_countries[]` |
| `GET /api/dashboard/attention` | yes | `kev_in_stack`, `kev_without_ticket`, `ransomware_in_client_scope`, `watchlist_hits`, `pir_hits`, `brief` (`headline`, `detail`) |
| `GET /api/dashboard/trending` | no | `items[]`: `kind` (`actor` / `ttp`), `name`, `ttp_id`, `count`, `prev_count`, `change_pct`, `is_new`, `daily[]` (7 or `days` buckets) |
| `GET /api/dashboard/ransomware` | no (client scope only in `attention`) | `weekly[]` (8 weeks: `week_start`, `victims`), `top_groups[]`, `total`, `apac` |
| `GET /api/dashboard/cve-exposure` | yes | `items[]` (top N: `cve_id`, `tech`, `cvss`, `cisa_kev`, `ticket_id`, `ticket_age_days`, `public_poc`), `open_critical`, `open_kev`, `closed_in_period`, `mean_days_to_close` |
| `GET /api/articles?sort=priority` | no | existing response; new `sort` query param (see 5.3) |

Definitions:

- **Incident articles per country**: articles with `confirmed_incident = true` in the period, counted
  per `article_countries.country_code`, any role, one count per article per country.
- **Ransomware victims**: `ransomware_victims` by `discovered` (fallback `published`) in the period.
  "APAC" uses the same country list the Newsroom APAC panel uses.
- **Ransomware in client scope**: victims whose `country_code` is in the client's countries
  (`client_countries`). Clients have no industry field, so sector matching is not possible; the
  mockup's "sektor klien" wording becomes "negara klien".
- **KEV in stack / open critical**: the same scope as `GET /api/cve/stats` (active client, active tech
  stack entries, false positives excluded), filtered on `cisa_kev` and on critical severity. "Open"
  means not acknowledged as closed by the existing ack statuses. "Without ticket" = no `cve_tickets`
  row for that CVE and client.
- **Watchlist hits**: articles in the period mentioning a threat actor in the client's `ta_watchlist`.
- **PIR hits**: number of active PIRs of the client with at least one matching article in the period,
  reusing the matching used by `GET /api/pir/{id}/articles`. If that matching is too slow to run for
  every PIR on each dashboard load, the plan must measure it first; the fallback is caching the
  result for 15 minutes, as `spike.py` does.
- **Trending**: count per actor (`article_threat_actors`) and per TTP (`article_ttps`) in the period
  vs the same-length previous period. `change_pct` only when `prev_count >= 3`; otherwise the item is
  marked `is_new` if `prev_count == 0`. Ranked by `count - prev_count`, minimum `count` of 3, top 10.
  For "All time" the endpoint uses the last 7 days vs the 7 before (labelled in the response).
  This is a new function, not `spike.py`'s z-score, because the z-score needs a 30-day baseline and
  does not cover TTPs; `spike.py` and `/api/spikes` stay unchanged for the Early Warning page.

Every new response model goes in `apps/api/src/cti_api/schemas/`, then `tools/export_openapi.py` and
`pnpm run gen:api` regenerate the contract.

## 5. Newsroom

### 5.1 Page structure (top to bottom)

1. **Tabs**: "Cyber News" and, for admins only, "Filtered Articles" (unchanged).
2. **Masthead**: title, date, article count for the period, and one filter row: period chips, "Insiden
   saja", country, and a search box (title, actor, CVE text). The filter row replaces today's
   `FilterBar` draft/apply pair with immediate filters (debounced 300 ms for search). Every section
   below uses the same filters, as today.
3. **Front**: lead story (largest type) + side column of the next three stories, from
   `GET /api/articles?sort=priority&page_size=4`.
4. **Topik aktif**: up to four topic cards from `GET /api/newsroom/topics` (same trending function as
   4.4, actors and TTPs). Each card: kind, change badge, name, article count, top countries, a 7-bar
   mini chart, the newest article, and "N artikel →". Clicking a card opens a side sheet with all
   articles for that topic (paged, `threat_actor=` filter for actors; a new `ttp=` filter for TTPs).
5. **Rubrics**: APAC, Global, Local, Ransomware in four columns at `lg` (two at `md`, one on mobile).
   Three items each, the section count in the header, and "Lihat semua →" that opens the same side
   sheet listing that rubric with paging. Each rubric keeps the query its current panel uses
   (`news_type` lists for APAC/Global, the Local panel query, the ransomware victims endpoint).
6. **Watchlist** and **Tech stack** rubrics: shown only when they have hits, same queries as the
   current `watchlist-panel.tsx` and `techstack-panel.tsx`.

Clicking any article opens the existing `ArticleModal`.

### 5.2 New / changed API

| Endpoint | Change |
| --- | --- |
| `GET /api/newsroom/topics` | New. Same params as `/api/articles` filters that make sense for counts (`posted_on_start/end`, `country`, `news_type`, `search`). Returns trending items plus, per item, `top_countries[]` and `latest_article` (`id`, `title`, `posted_on`). |
| `GET /api/articles` | New optional `sort` (`recent` default, `priority`) and `ttp` (list of TTP IDs) params. |

### 5.3 Priority ordering

Articles have no severity field. "Priority" orders by, in this order: `confirmed_incident` desc,
`confidence_score` desc (nulls last), `seen_count` desc (picked up by more sources), `posted_on`
desc, `id` desc. The badge on cards shows "Insiden" when `confirmed_incident` is true and the
confidence score as a number; the mockup's "Kritis / Tinggi" labels are replaced by these, so no
severity is invented. Watchlist and tech stack matches show as their own chips.

### 5.4 Component changes

- `app/(app)/newsroom/page.tsx`: new layout.
- New `components/newsroom/front-section.tsx`, `topics-strip.tsx`, `rubric.tsx`,
  `article-list-sheet.tsx` (side sheet with paging, reused by topics and "Lihat semua").
- The five `panels/*.tsx` files are replaced by `rubric.tsx` instances; their query logic moves into
  hooks in `use-articles.ts` (or a sibling hook file) so each rubric keeps the same data source.
- `filter-bar.tsx` is replaced by the masthead filter row. `lib/newsroom/filters.ts` keeps the filter
  type; the draft state goes away.
- `article-modal.tsx`, `filtered-view.tsx`, `d3fend-toggle.tsx`: unchanged.

## 6. Error, loading and empty states

- Each dashboard section and Newsroom block has its own skeleton sized like the final content, and
  its own error line ("Gagal memuat …") without hiding the other sections.
- Period changes keep the previous numbers visible and dimmed (`keepPreviousData`), as today.
- Empty states are written for each block, for example the map with no points shows the dot map
  and "Belum ada insiden dengan negara pada periode ini."; trending with no items says no entity
  passed the threshold.
- The map tooltip and the side sheet work with keyboard and screen readers (focus trap in the sheet,
  `Escape` closes).

## 7. Testing

- **API unit tests** (`tests/unit`): trending math (`change_pct`, `is_new`, threshold, ranking),
  brief text for the normal case and the "nothing notable" case, priority sort key.
- **API integration tests** (`tests/integration`, testcontainers Postgres): each new endpoint with
  seeded articles, victims, CVEs, tickets and watchlist rows; client scoping (client A never sees
  client B's KEV or watchlist counts); `sort=priority` and `ttp=` on `/api/articles`.
- **Contract**: regenerate `docs/openapi.json` and `schema.d.ts`; CI drift check.
- **Web**: no test runner exists; CI runs lint, typecheck, build. Manual check in the browser on the
  dev instance (read-only) at 1440 px and 375 px, light and dark, keyboard through the map, sheet and
  modal.

## 8. Delivery plan (PRs)

Each PR is mergeable on its own, ships behind no flag, and carries its version bump and
`CHANGELOG.md` entry per the release convention.

1. **Login** (web only, small). Includes `world-dots.tsx` without points.
2. **Dashboard API**: service, repositories, endpoints, schemas, tests, regenerated contract.
3. **Dashboard web**: new page layout using the PR 2 endpoints, map points, cards.
4. **Newsroom API**: `/api/newsroom/topics`, `sort` and `ttp` on `/api/articles`, tests, contract.
5. **Newsroom web**: new page layout, sheet, rubrics.

PR 2 and PR 4 share the trending function; PR 2 introduces it and PR 4 reuses it.

## 9. Risks and open points

- **PIR matching cost** (4.4): measured in planning; caching is the fallback.
- **Country centroids and land mask** are static data in the web bundle (a few KB); acceptable.
- **Ransomware dates**: some rows may lack `discovered`; the fallback to `published` is documented,
  rows with neither are excluded and counted in an `undated` field of `/api/dashboard/ransomware`
  so the gap is visible.
- **Removing the "Need Attention" band** drops its sector-incident figure. The sector view stays on
  the Exec page.
