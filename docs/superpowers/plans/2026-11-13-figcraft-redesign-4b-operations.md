# FigCraft redesign 4b: Operations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the full FigCraft mockups for Scrapers (tiles, table, side panel, Disable dialog) and Data Health (tiles, pipeline flow, calls-per-hour chart, compact cards) with every pre-redesign feature S1-S17 and DH1-DH12 still reachable, plus the three additive `GET /api/data-health` fields the mockup needs (B-DH1 `pipeline`, B-DH2 `queues.depths`, B-DH3 `llm.calls_per_hour`), inside the 0.8.16 release.

Then the web: shared scraper pieces and template-safe layouts (5), Scrapers (6-9: shell and toolbar, Sources table, side panel, dialogs and Run history sheet), Data Health (10-14: tones, shell and tiles, Pipeline and Needs attention, LLM gateway, Relevance and the row of three, More checks), a states and permissions sweep (15), docs (16) and the final verification (17). `routers/scraper.py` and every scraper endpoint stay untouched; the config form's logic is lifted, not rewritten.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2 (async), `redis.asyncio`, pytest + testcontainers; Next.js 16 App Router, React 19, TanStack Query, Tailwind v4, shadcn on Base UI (`@base-ui/react`), `openapi-fetch` (`api` from `@/lib/api/client`), Chart.js via `react-chartjs-2` (`components/ui/bar-series.tsx`), `lucide-react`, `sonner`.

**Spec:** `docs/superpowers/specs/2026-11-12-figcraft-redesign-4b-operations-design.md` (binding; section numbers below refer to it, `C`/`D`/`P` ids are its conflicts, decisions and flagged choices). ## Review Focus

1. Hour buckets do not move with the database session's `TimeZone`: a call at 14:10 UTC is in the 14:00 UTC bucket under `Asia/Kolkata` too, and an hour without calls is a zero entry, never a missing one (Task 3, `test_data_health_llm_calls_per_hour_ignores_session_timezone`).
2. A Redis failure part-way through the seven `LLEN`s nulls the whole block together with `enrich_depth`; the page never shows a half-filled queue list (Task 2, `test_data_health_queue_depths_all_or_nothing`).
3. Fractions and zero denominators: `holdout_agreement`, `holdout_band_share`, `band_agreement_14d` and `audit_agreement` arrive as 0-1 fractions and print as percentages; `processed_7d == 0`, a fleet of 0 and `total_articles == 0` print "0%" or "–", never `NaN%` or `Infinity` (Tasks 10, 11, 13 checklists on an empty `qafig` database).
4. The panel never shows another scraper's result: the dry-run slot and pending labels belong to the selected id and reset when the selection changes; a selected row that the filters hide keeps its panel; an unknown `?scraper=` id shows "Unknown scraper" and is not retried (Task 8 checklist).
5. A failed refetch never blanks the page or loops: Data Health keeps the last good numbers with the "Could not refresh" notice, a 403/404 is requested once, and the change to the shared `useScraperHealth` does not break the X Intel feed chip (Tasks 5, 10 and 15 checklists, blocking requests in the Network panel).
