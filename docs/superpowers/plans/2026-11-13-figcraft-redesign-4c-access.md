## Review Focus

1. **The typed password lives only in memory for the forced change.** After a forced change, a cancel, a failed re-login or a reload, neither password is in `localStorage`, `sessionStorage`, `document.cookie`, the URL, the console or the React Query cache / mutation variables, and the sign-in password state is empty after step 2 (Task 7 checklist, "Password lifetime" line; Task 18 grep).
2. **Re-login after revocation.** A sign-in in the same second as the password change gets a token that is already revoked; the 1,200 ms wait (P10) prevents it, and when the re-login still fails the user lands on the sign-in stage with "Password changed", never on a dead page or a loop (Task 1 `test_token_issued_in_revocation_second_is_revoked` pins the server rule and `test_change_password_clears_force_pw_change` the flow; Task 7 checklist, "Re-login" line, repeated ten times).
3. **The 401 dialog shows once, with no loop.** Several queries failing with 401 at the same moment open one dialog and send one logout POST; no request reaches `/api/proxy` while the store is not `active`; a deliberate sign-out and a full load with a dead cookie open no dialog; `/login` never bounces to `/dashboard` and back (Task 5 checklist, "Once" and "No loop" lines).
4. **The `Retry-After` clamp, both sides.** Server: TTL -2, -1, 0 and 999 all become 60, so the header is always 1-60 (Task 3, `test_retry_after_seconds_clamps_ttl`). Browser: "0", "abc", "99999" and a missing header become `null` → 60 s, so the button can never stay disabled forever (Task 6 checklist, "Clamp" line).
5. **B-A1's keyword-only `force_change`.** No default, so a caller that forgets it fails at import-time type check and at call time; both existing callers and the one existing test call are updated in the same commit, and a self change still clears the flag (Task 1, `test_reset_password_self_change_clears_force_pw_change`, `test_reset_password_admin_reset_sets_force_pw_change`, mypy, and the grep in Step 4).
